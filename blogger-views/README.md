## 每条观点必须带的三样

1. **原文**（逐字，不翻译不改写；X 自动译文的要标注「译文」）
2. **时间**（精确到小时，或日期级并注明）
3. **历史标签**：该账号在能力评测里的位置（大周期偏准 / 历史以错误为主 / 样本不足 / 无历史基准）

> 2026-11-13 的教训：只截事件窗口会系统性奖励**顺势者**，所以标签栏必须写「这波看对」而不是「提前预判」；`@huangdaobtc` 就因此从 S 级降为 B 级。

## 分级（事件复盘用）

| 级别 | 含义 |
|---|---|
| S | 提前看空/看多 + 全程未改口 + 给到关键位 + **历史一致性成立** |
| A | 方向对，但留了余地 / 样本少 / 自述未验证 |
| B | 方向对，但中途中喊过反向（如喊底），或机制是顺势 |
| C | 在关键拐点明确看反（如 75–80k 喊底） |

## 每期必含模块

1. 事件与行情快照（KPI + 时间线）
2. 分级名单（每级附原文）
3. 点位共识（提及次数 + 谁在说）
4. 多空阵营对照
5. 与历史评测的交叉验证
6. 方法与局限（抓取覆盖、译文、事后视角偏差）

## 更新流程

1. 新建 `<YYYY-MM-DD>/index.html`，引用 `../../assets/report.css`
2. 博主名一律用 `<a class="handle" href="https://x.com/<handle>">@handle</a>`（新标签打开）
3. 同日修订：直接覆盖该目录并更新页脚「修订」；跨阶段大改则新建 `-r2/`
4. 更新本 README 版本表与专题首页卡片
