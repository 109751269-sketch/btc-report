为什么要有台账：平时大家只会记住「谁说得响」，不会记住「谁后来错了」。这套机制把每句可量化的话变成一张到期自动结算的承诺——目标位、起算日、结算日、判据全部固定，避免事后解释。

一、判定类型（写死，不临场解释）

类型含义判据
down喊跌到某价位窗口内最低价 ≤ 目标 → 对；到期没到 → 错
up喊反弹/涨到某价位窗口内最高价 ≥ 目标 → 对；到期没到 → 错
bottom / hold喊某价位是底 / 支撑守住最低价跌破 目标×0.97 → 错；未破 → 到结算日判对
reject某价位「难成支撑/阻力」连续 2 日收盘站上该位 → 错
observe条件式 / 无点位不计分，只观察

五、拉黑规则

  1. 极端看空（≤60k）：到期未跌到、且期间已反弹站上 70k → 拉黑（对应「瞎喊点位」）。
  2. 看底派：被跌破 level×0.97 → 降级；累计 2 次 → 拉黑。
  3. 极端看多目标（如 105k）：到期未达 → 按同一规则处理。
  4. 同一人同期给方向相反的硬目标 → 标注并单独判：@huangdaobtc 11-13 既说「最终跌破 49000」，又说「62.5–67.5k 做多、目标 75k」，两条都在台账里。

注：单次判错只降级，不直接拉黑——除非是极端点位连续落空（规则 1）。这样避免把「方向对但幅度保守」的人和「纯瞎喊」的人混为一谈。

六、方法与局限

  • 台账与判定器：state/calls_ledger.json（30 条）+ verify_calls.js（五类判据）；每轮自动拉行情判定并写回，人工不参与改判。
  • 只用原文：每条都存逐字 quote；博主自述（如「我是一直看空」）不作为证据。
  • 容量偏差：bottom 型用「是否跌破 3%」近似判断「底成不成立」，无法区分「横盘磨底」与「真反转」；后续可加「是否在 N 日内反弹 ≥X%」作为二次判据。
  • 时间粒度：判定用日线，盘中插针可能被日线吞掉；对极短周期的观点不适用。
  • 本页为机械判定结果，不代表对博主整体能力的最终评价（能力评测见 11-12 期 与 11-11 期）。
