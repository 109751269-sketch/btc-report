# btc-report

BTC 相关公开报告站点（GitHub Pages）：**https://109751269-sketch.github.io/btc-report/**

## 三个专题

| 专题 | 目录 | 回答什么问题 |
|---|---|---|
| 01 宏观走势与重要事件 | `macro-events/` | 行情走到了哪、为什么（驱动事件、关键价位、时间线）。不做博主评价 |
| 02 博主预测能力打分 | `blogger-scoring/` | 谁有稳定的判断力（超额胜率、周期分层、顶底预判、观点台账结算、拉黑建议） |
| 03 博主观点与走势预测 | `blogger-views/` | 这几天谁说了什么、点位共识在哪、某次事件里谁提前看对/看错（附原文与历史标签） |

每个专题下按 **日期** 版本化：`<专题>/YYYY-MM-DD/index.html`。同日重大修订用 `YYYY-MM-DD-r2/`，不覆盖历史。

## 结构与改版规则

```
.
├── index.html                 # 三专题导航
├── assets/report.css          # 全站统一样式（改版只改这里）
├── _template/                 # 报告骨架 + 写法说明
├── macro-events/              # 01
│   ├── index.html             # 专题首页（版本列表）
│   ├── README.md              # 定位 + 必含模块 + 更新流程
│   └── YYYY-MM-DD/index.html
├── blogger-scoring/           # 02（同上）
├── blogger-views/             # 03（同上）
└── 2026-11-08/ 2026-11-11/    # 旧路径，保留兼容
```

- **样式统一**：新报告引用 `assets/report.css`；改版式只改这一个文件，历史自包含样式的报告不受影响
- **页内导航（强制）**：每份报告顶部固定面包屑 `首页 / <编号> <专题名> / <YYYY-MM-DD>`，前两级均可点回上一级与首页；不要再加右上角浮动返回按钮
- **专题边界（强制）**：**同一份事实只在一个专题里维护**
  - 行情时间线、驱动事件、关键价位结构 → 只在 **01**
  - 谁说了什么、谁提前看对/看错、分级名单 → 只在 **03**；03 如需行情背景，只写 3 个数字 + 一句话归因，再链到 01 的具体一期
  - 打分口径、台账判定 → 只在 **02**
  - 首页三张专题卡整卡可点（不要放「进入专题」按钮）
- **内容订正**：同一期直接覆盖原目录，并在页脚更新「修订」说明
- **跨版本改版**：新建 `-r2/` 目录，旧版保留
- **新增一期**：复制 `_template/report.html` → 替换占位符 → 更新专题 README 版本表与专题首页卡片

## 分析代码在哪

本仓库**只放已发布的报告页面**。

生成报告的分析管线（抓取、冻结、LLM 抽取、审计、打分、观点台账、HTML 生成）在技能仓库：

- 技能仓库：https://github.com/109751269-sketch/web-analysis-ai
- 技能内路径：`topics/btc-analyst/`
- 结论文档：`topics/btc-analyst/FINDINGS.md`
- 数据：不随技能仓库分发，由 `paths.js` 从工作区 `topics-data/btc-analyst/` 解析，可用 `BTC_DATA_DIR` 覆盖

原 `analyses/btc-analyst/` 目录已于 2026-11-12 移除，避免同一份代码在两个仓库分叉。

> 所有内容为公开信息整理与观点汇总，不构成投资建议。
